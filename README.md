# HADE · 可迁移协作系统（工程候选版）

让协作约束随项目一起保留：先理解目标、在授权范围内连续执行、保护已有数据、按真实结果判断改进。

这是公共协作机制与本地安装/反馈工具，不是原维护者的私人档案，也不提供一个独立于模型运行的意识、自动赚钱服务或“永不停机”的承诺。它通过 Codex 原生指令入口交付，不需要每次点名 Skill；指令是否改变行为仍要用实际任务检验。

## 最短使用路径

需要一个正常登录、可以操作本地项目的 Codex，以及 Node.js（本次测试为 Windows + Node 24）。不需要 Git、npm 安装或编译，不分发模型账号或 API Key。

把解压后的文件夹交给 Codex，并说明：

> 请阅读本包说明，把 bundles/0.1.0-preview.4 安装到我指定的项目。先展示目标路径和原规则的整合差异，保留我已有的内容；按 install/README.md 使用安装器，不改账号或安全设置。安装后检查新会话实际收到的内容。

首次必须确定目标项目，不能猜测。安装器先预览、再根据同一预览哈希应用；这不是每一步都要用户敲口令，而是防止过期方案覆盖已经改变的文件。已授权的同范围确定步骤可由协作者连续完成。

建议先在一个小项目尝试。现用规则很大或有 override 时先核对实际发现链和容量，不能为了安装本包删薄个人规则。详细命令及 API 在 [安装器说明](install/README.md)。

## 自己定制、更新和移除

- 修改安装目标的 `.hade-public/RECIPIENT.md`，再执行 `refresh`。不要直接修改 AGENTS 中的托管片段。
- 升级使用新版本的 `update`。回退选择已保留的安装回执；它保留你当前的配置及托管片段以外后来增加的文字。
- `uninstall` 仅移除公共片段。个人配置、原有规则和历史快照保留，不自动清理用户文件。
- 本地备份含你的原指令，默认不上传。写入中断时保留现场和快照，不用旧整文件盲目覆盖新内容。首版不是断电原子事务，也不是对抗恶意并发的安全系统。

## 怎样吸收反馈

[反馈模块](feedback/README.md) 默认离线、本地、不上传。反馈先成为惰性数据，再由维护者提出独立候选、固定验收、执行实际内容检查；结果分为接受、拒绝、证据不足。接受不等于安装或发布，应用/撤销另有明确记录。

这里的自动检查只证明其列出的文件内容约束。没有独立语义证据时，不能凭哈希或自评分宣称“人格成长”。三份核心文档的有效版本可以导出成安装器可消费的包；撤销反馈版本也不会神奇地撤销已经装到别处的副本，仍需在相应目标执行回退。
