# Public source and distribution boundary

The selected versioned core bundle is an original public rewrite of maintained collaboration mechanisms, not an export of the private canonical body. It omits personal history, private absolute paths, account details, raw conversations, original quotations and personal visual preferences. Older local previews are retained privately as explicit lifecycle/feedback baselines, not represented as previously published releases and not automatically included in the distribution.

The current CORE preserves twelve public mechanism areas. Preview.2 added explicit handoff from decisions to implementation, early prerequisite checking, and checking for necessary successors before ending a turn. Preview.3 added a bounded open-discussion rhythm; preview.4 replaces that one paragraph with a dialog-act stopping boundary after an observed failure within the sentence bound. Earlier failures remain failures. Content checks do not establish better natural behavior. HOST-CODEX and the blank RECIPIENT template remain unchanged original public operation contracts. Recipient-owned configuration is not a publisher asset and is excluded from distribution.

Installer and feedback implementation origins are described in their own SOURCE-REVIEW files. They use only Node built-in modules; there is no copied third-party implementation or package-manager dependency in the allowlisted runtime. README and release summaries are original documentation. Public-original licensing follows the delegated MIT decision; unknown input bundles and user data are not relicensed.

Mandatory publisher allowlist: README.md, LICENSE, SOURCE-REVIEW.md, current bundle CORE.md/HOST-CODEX.md/RECIPIENT.example.md/release.json, reviewed installer runtime and documentation, reviewed feedback runtime and documentation, and a separately reviewed public evidence summary. Source tests may be included only after reviewing their invented fixtures. No glob-based directory upload.

Do not publish generated synthetic-tests/synthetic-runs, native session files, previews containing receiver text, auth/config files, private derivation maps, project status documents or receiver .hade-public folders. Hashes prove unchanged bytes, not copyright ownership, semantic equivalence, input isolation or behavioral reliability. Final archive review must still inspect the actual selected bytes.
